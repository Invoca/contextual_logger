## Executive Summary

`contextual_logger` is a small, mature Ruby **library gem** (≈390 lines across 8 files in `lib/`)
that adds structured, layered context to an existing Ruby logger. It is published to RubyGems,
consumed by Invoca services, and owned by the `octothorpe` team under the
`platform-observability` system (`catalog-info.yaml`).

Three things define nearly every design decision in it:

1. **It is a mixin, not a wrapper.** The gem is `extend`ed onto a host application's existing
   `::Logger` instance (or `include`d in their `Logger` subclass). It therefore runs inside
   someone else's namespace and must not disturb it.
2. **It must stay interface-compatible with `::Logger`.** Specifically `#add`'s positional
   arity, because `ActiveSupport::Logger.broadcast` and plain `::Logger` callers depend on it.
3. **It is on the hot path.** Every log line in every consuming service passes through
   `deep_merge_with_current_context`, `format_message`, and `redact`. Per-line allocation is
   avoided deliberately and repeatedly.

The repository is in steady maintenance: v1.5.0 (2025-09-12), a slow and deliberate release
cadence, careful SemVer, a maintained CHANGELOG, and a multi-version CI matrix that is the main
source of ongoing work (supporting new Ruby and ActiveSupport releases).

### Purpose

Give a Ruby logger the ability to carry context — process-global, block-scoped, and inline —
merge it with correct precedence, emit it as structured JSON, and redact registered secrets
from the result.

### Key Architectural Principles

| Principle | Where it shows up |
|---|---|
| Add behaviour by mixin; never take ownership of the host's object | `LoggerMixin`, `BroadcastLoggerMixin`; `ContextualLogger.new` deprecated |
| One merge helper owns context precedence | `deep_merge_with_current_context` |
| Per-instance, fiber-local override storage | `Context#thread_context_key_for_logger_instance` |
| One write choke point, so redaction cannot be bypassed | `LoggerMixin#write_entry_to_log` |
| Generate repetitive surfaces from a single table | `LOG_LEVEL_NAMES_TO_SEVERITY` drives three generation sites |
| Fail loudly at the boundary, not deep in a merge | `ArgumentError` on bad level, non-mixin logger, string context keys |
| Patches to other gems are opt-in | `lib/contextual_logger/overrides/`, never auto-required |
| Deprecate across a major; never remove silently | `ActiveSupport::Deprecation`, `TODO … in v2.0` |
| Accepted tradeoffs are written down at the site | `LoggerWithContext#global_context` memoization note |

## Architecture

### Component Organization

```
ContextualLogger                      (lib/contextual_logger.rb)
├─ LOG_LEVEL_NAMES_TO_SEVERITY        frozen name → ::Logger::Severity table; drives codegen
├─ .normalize_log_level               public helper — Integer or name → severity Integer
├─ .normalize_message                 public helper — String passthrough, else #inspect
├─ .new                               DEPRECATED (removal in 2.0)
├─ .global_context_lock_message       module accessor  (global_context_lock_message.rb)
├─ GlobalContextIsLocked < StandardError
│
├─ module LoggerMixin                 the main surface; extend/include onto a ::Logger
│   ├─ include Context                thread/fiber-local override storage
│   ├─ global_context / global_context= (frozen; locked once an override is taken)
│   ├─ current_context                override || global
│   ├─ with_context(ctx) { }          block form (ensure-reset) or ContextHandler form
│   ├─ debug/info/warn/error/fatal/unknown   GENERATED from the table
│   ├─ add(severity, arg1, arg2, **context)  ::Logger-compatible arity
│   ├─ write_entry_to_log(...)        the single write + redact choke point
│   ├─ format_message / basic_json_log_entry
│   └─ redactor (private, memoized)   delegates register_secret, register_secret_regex, redact
│
├─ module BroadcastLoggerMixin        for ActiveSupport::BroadcastLogger (AS 7.1+)
│   └─ level methods + add            GENERATED; each dispatches to every child logger
│
├─ module Context                     (context.rb)
├─ class  ContextHandler              (context_handler.rb)   reset token for the non-block form
├─ class  Redactor                    (redactor.rb)          Set of patterns → one alternation regex
├─ class  LoggerWithContext           (logger_with_context.rb) delegating logger, own level
└─ overrides/                         opt-in monkey patches of OTHER gems
    └─ ActiveSupport::TaggedLogging::Formatter   folds tags into context as :log_tags
```

Responsibilities are narrow and non-overlapping: `Context` owns *where* an override lives,
`ContextHandler` owns *undoing* one, `Redactor` owns secret matching, `LoggerWithContext` owns
delegation plus an independent level, and `LoggerMixin` owns the merge/format/write pipeline.

### Data Flow — one log line

```
logger.info("started", log_source: "redis")
  │
  ├─ generated #info                       (contextual_logger.rb:101-117)
  │    dispatches on (arg?, context?, block?) → add(INFO, …)
  │
  └─ #add                                  (contextual_logger.rb:125-144)
       ├─ log_level_enabled?(severity)  ──► false → return true, block NEVER evaluated
       ├─ resolve message / progname from the (arg1, arg2, block) shape
       ├─ deep_merge_with_current_context(context)
       │     current_context = current_context_override || global_context
       │     Thread.current[:"…context_for_<object_id>"]  ←─ with_context layer
       └─ #write_entry_to_log
            ├─ #format_message
            │    ├─ normalize_message(message) / normalize_message(progname)
            │    ├─ @formatter ? @formatter.call(…, { message:, **context })
            │    └─ : basic_json_log_entry → { message, severity, timestamp, **context }.to_json
            ├─ redactor.redact(line)        single alternation regex → "<redacted>"
            └─ @logdev&.write(line)
```

For a `LoggerWithContext`, `write_entry_to_log` is overridden to merge its own context and then
forward to the base logger's `write_entry_to_log` — so the base logger's formatter, log device,
**and redactor** are the ones that run.

### Context Precedence

Five layers, innermost wins, resolved by `deep_merge`:

| # | Layer | Stored where |
|---|---|---|
| 1 | inline `**context` on the call | argument, merged last |
| 2 | `with_context` on the `LoggerWithContext` | its own fiber-local slot |
| 3 | context passed to `LoggerWithContext.new` | `@context`, merged into its memoized `global_context` |
| 4 | `with_context` on the base logger | base logger's fiber-local slot |
| 5 | `global_context` on the base logger | `@global_context` (frozen) |

Asserted end to end by `spec/lib/contextual_logger/logger_with_context_spec.rb`
("implements the full context from 1 to 5").

### Service Boundaries

Per [`../architecture/overview.md`](../architecture/overview.md) (derived by
`architecture-pipeline generate`, `max_depth: 2`):

- **Lib Contextual Logger** (LEAF) — the six coupled files under `lib/contextual_logger/`.
- **Root** (LEAF) — `lib/contextual_logger/overrides/**` and `lib/contextual_logger/version.rb`,
  directory-banded because they have no measured coupling to the cluster. That is the correct

client, and no external service calls — its only integration surfaces are the Ruby standard
library (`::Logger`), ActiveSupport, and whatever log device the host hands it.

- Symbol-only context keys, enforced at runtime.
- `and`/`or` in guard position; `&&`/`||` for boolean values.

## Common Patterns

The full catalogue with DO/DON'T examples is in [`patterns.md`](patterns.md). The thirteen
documented patterns:

1. Extend by mixin, never by wrapping
2. Context precedence by deep merge, resolved innermost-first
3. Per-instance thread/fiber-local storage keyed by `object_id`
4. Explicit reset token (`ContextHandler`) for non-block scoping
5. Generate the level methods from one table
6. Normalize at the boundary, once
7. Validate the caller's contract loudly, at construction
8. Redaction: one compiled alternation regex, rebuilt only on change
9. Qualify constants with `::` in library code
10. Opt-in monkey patches under `overrides/`
11. Require order is a load-bearing detail
12. Support multiple dependency versions with an appraisal matrix
13. Write the tradeoff down next to the code

## Anti-Patterns

The full list with alternatives is in [`anti-patterns.md`](anti-patterns.md). The fifteen
documented anti-patterns, in short: wrapping instead of mixing in; changing `#add`'s positional
signature; evaluating the message block before the level check; string context keys; mutating a
stored (frozen) context; setting `global_context` after an override locked it; bypassing
`write_entry_to_log`; auto-requiring an `overrides/` file; unqualified constants; allocating on
the no-context path; hand-writing what the level table generates; hand-editing generated files
(`gemfiles/`, `catalog-info.yaml`); letting the README drift from the gemspec; silently dropping
a deprecated API; and specs that assert on mocked log output.

## Integration Patterns and External Dependencies

This gem has **no outbound integrations** — no HTTP clients, no database, no message queue, no
credentials of its own. Its integration surface is entirely *inbound*: other libraries' objects
that it extends or patches.

| Surface | How it is integrated | Risk |
|---|---|---|
| `::Logger` (stdlib) | `LoggerMixin` is extended onto an instance; `#add` arity preserved | an arity change breaks every classic caller |
| `ActiveSupport::Logger.broadcast` (≤7.0) | survives because `add` keeps three positionals and uses `**context` | documented in CHANGELOG `0.5.1` |
| `ActiveSupport::BroadcastLogger` (7.1+) | separate `BroadcastLoggerMixin`, generated dispatch to each child | all children must themselves be contextual loggers |
| `ActiveSupport::TaggedLogging::Formatter` | opt-in override, folds `current_tags` into context as `:log_tags`; always calls `super` | a required-by-default patch would affect every consumer |
| Host-supplied `@formatter` | if set, receives `{ message:, **context }` as the message argument; otherwise the built-in JSON entry is used | a formatter that assumes a String message will break |
| Host-supplied `@logdev` | written to via `@logdev&.write` — safe-navigated | nil logdev is tolerated, not an error |

**Secrets.** The only security-relevant mechanism is redaction. Secrets are registered per
logger instance (`redactor` is memoized per object), escaped with `Regexp.escape` for literals,
and applied once to the fully-formatted line. See `anti-patterns.md` §7 and the troubleshooting
entry "A registered secret still appears in the log".

## Configuration Management

There is almost none, by design — the gem is configured through its own API, not through
environment variables or config files.

| Configured thing | Mechanism | Notes |

## Testing Strategy

- **RSpec**, ~1063 lines of spec against ~390 lines of library — the suite is deliberately
  larger than the code, because the public contract (seven call arities × six levels × five
  context layers) is combinatorial.
- Specs exercise **real `::Logger` objects writing to `StringIO`**, then assert on the output.
  Mocking the method under test is an anti-pattern here.
- JSON log lines are compared **semantically** via the `a_json_log_line_like` matcher.
- Time is frozen with the `Time.now_override` shim in `spec/spec_helper.rb`.
- `Helpers` (auto-included) provides `log_at_every_level`, `log_message_at_every_level`,
  `log_message_levels`.
- Every context-touching spec resets `ContextualLogger.global_context_lock_message` in an
  `after` hook — process-global state otherwise leaks across examples.
- `verify_partial_doubles = true`.
- Coverage reports to Coveralls; **no enforced threshold** in-repo.
- CI runs `bundle exec rspec` across 2 Rubies × 5 gemfiles = 10 combinations,
  `fail-fast: false`. RuboCop is **not** run in CI.

**Gap worth knowing.** The merge gate is RSpec only. Lint and coverage are advisory.

## Decision Rationale and Trade-offs

**Why a mixin rather than a wrapper or a subclass?**
A wrapper breaks `is_a?(Logger)` in host code and in Rails, and must forward the entire
`::Logger` surface. A subclass cannot be applied to a logger the host already constructed.
`extend`/`include` keeps object identity and inherits everything the gem does not override.
The cost — running inside the host's lexical scope — is paid with the `::`-qualification
convention. `ContextualLogger.new` (the wrapper constructor) was deprecated in `0.7.0`.

**Why `**context` on `#add` rather than a fourth positional parameter?**
`ActiveSupport::Logger.broadcast` re-implements `add(severity, message, progname)`. Ruby binds a
trailing hash to `**context` when one is present and to `progname` when the method is called
classically — so one method serves both. This is the single most constraint-driven decision in
the gem (CHANGELOG `0.5.1`, comment at `contextual_logger.rb:91-99`).

**Why fiber-local storage keyed by `object_id`?**
`Thread.current[…]` is fiber-local, which is what gives correct scoping under concurrent request
handling. The `object_id` in the key prevents one logger's `with_context` from leaking into
another logger used in the same thread. Introduced in `1.2.0`, replacing a design where context
lived outside the logger instance.

**Why lock `global_context` once an override exists?**
Changing process-global context while scoped overrides are live would produce context that
differs per thread for reasons unrelated to the code. Failing loudly
(`GlobalContextIsLocked`, with a message naming what took the lock) was chosen over silently
inconsistent logs. The cost is that the lock is process-global, so one logger locks all of them —
and specs must reset it.

**Why reject string context keys instead of normalizing them?**
Normalizing (`0.11.0`) meant `'id'` and `:id` collided silently and one value won. Rejecting
(`1.5.0`) makes the ambiguity the caller's to resolve. This was a deliberate breaking change,
recorded in the CHANGELOG.

**Why `inspect` rather than `to_json` for non-String messages?**
`to_json` turned `nil` into JSON `null` and `false` into JSON `false`, indistinguishable from a
genuinely null field. `inspect` logs `"nil"` and `"false"` as strings. Changed in `0.6.0` to
restore `::Logger`'s ability to log non-string messages.

**Why generate methods with `class_eval` on a string rather than `define_method`?**
The generated bodies branch on argument shape and call `add` with a literal severity constant.
A string-eval'd body compiles to a plain method with no closure capture and no per-call hash
lookup — which matters on a logging hot path. `__FILE__, __LINE__ + 1` is passed so backtraces
still point at real source.

**Accepted limitation: `LoggerWithContext#global_context` memoization.**
Merging the base logger's `current_context` once, at first use, misses context from a
`with_context` block entered *afterwards*. The alternative is a `deep_merge` per log line. The
tradeoff is recorded as a `TODO` at `logger_with_context.rb:28-30` rather than silently accepted.

**Known drift, not yet resolved.** `README.md` advertises *Ruby >= 2.6, ActiveSupport >= 4.2, < 7*,
while the gemspec requires `activesupport >= 6.0` and CI tests Ruby 3.3/3.4 against ActiveSupport
7.0–8.0. The README also still carries a Travis CI badge although CI moved to GitHub Actions
(`TECH-5896`). Both are documentation-only and are good first issues.
